# 動作言語仕様

## 1. 目的

本仕様は、3次元関節座標から関節角度を計算し、動作言語へエンコードする処理と、動作言語をデコードして3次元座標へ再構成する処理の仕様である。

処理全体は次の流れで構成する。

```text
COCO 17点の3次元座標
  -> 親関節基準のEuler角 [Roll, Pitch, Yaw]
  -> 量子化された動作言語
  -> Euler角
  -> 骨格の3次元座標
```

## 2. 現行実装

| 処理 | 実装 |
|---|---|
| 座標 -> 角度 | `src/pose_estimation/calculate_joint_angles.py` |
| 軸・関節・可動域定義 | `src/pose_estimation/motion_config.py` |
| 角度 -> 動作言語、動作言語 -> 角度 | `src/pose_estimation/motion_language.py` |
| 角度 -> 座標、可視化 | `src/pose_estimation/visualize_motion.py` |

角度の単位は度、座標の単位は入力座標系に依存する。可視化用の骨長はメートル相当の固定値を使用する。

## 3. 座標入力

### 3.1 入力形式

入力はNumPy配列または同等の数値配列とし、形状は次のとおりとする。

```text
(frames, 17, 3)
```

各フレームの17点はCOCO Pose順序である。

| index | 名称 |
|---:|---|
| 0 | nose |
| 1 | lefteye |
| 2 | righteye |
| 3 | leftear |
| 4 | rightear |
| 5 | leftshoulder |
| 6 | rightshoulder |
| 7 | leftelbow |
| 8 | rightelbow |
| 9 | leftwrist |
| 10 | rightwrist |
| 11 | lefthip |
| 12 | righthip |
| 13 | leftknee |
| 14 | rightknee |
| 15 | leftankle |
| 16 | rightankle |

全要素は有限な数値でなければならない。欠損点やゼロ長の骨ベクトルがある場合、角度計算はエラーになる。

### 3.2 内部関節構造

角度配列は現在15関節、形状 `(frames, 15, 3)` である。

| joint_idx | 関節 | 親 |
|---:|---|---|
| 0 | hips | なし |
| 1 | neck | hips |
| 2 | head | neck |
| 3 | L_shoulder | neck |
| 4 | L_elbow | L_shoulder |
| 5 | L_wrist | L_elbow |
| 6 | R_shoulder | neck |
| 7 | R_elbow | R_shoulder |
| 8 | R_wrist | R_elbow |
| 9 | L_hip | hips |
| 10 | L_knee | L_hip |
| 11 | L_ankle | L_knee |
| 12 | R_hip | hips |
| 13 | R_knee | R_hip |
| 14 | R_ankle | R_knee |

## 4. 座標から角度への変換

### 4.1 補助点

入力点から次の補助点を作る。

```text
hips = (lefthip + righthip) / 2
neck = (leftshoulder + rightshoulder) / 2
head = mean(nose, lefteye, righteye, leftear, rightear)
```

左右の肩、肘、手首、股関節、膝、足首は対応するCOCO点をそのまま使用する。

### 4.2 関節フレーム

方向ベクトル `direction` と基準ベクトル `reference` から直交座標系を作る。

```text
x = normalize(direction)
y = normalize(reference - dot(reference, x) * x)
z = normalize(cross(x, y))
y = normalize(cross(z, x))
F = [x y z]  # 各列がローカル軸
```

hipsのフレームは次で作る。

```text
direction = rightshoulder - leftshoulder
reference = neck - hips
```

その他の関節は、子関節方向を `direction` とする。子関節がない場合は、親から対象関節への方向を使用する。headだけは次を使用する。

```text
direction = nose - head
reference = rightear - leftear
```

### 4.3 親基準のEuler角

親関節のフレームを `F_parent`、対象関節のフレームを `F_joint` とすると、相対回転は次で求める。

```text
R_relative = transpose(F_parent) @ F_joint
```

ルートのhipsはワールド基準として扱う。

`R_relative` をEuler角へ変換する際の回転順序は `zxy`、単位は度である。

実装上の出力配列の最後の次元は次の順序とする。

```text
[Roll, Pitch, Yaw] = [Z回転, X回転, Y回転]
```

## 5. 動作言語の軸定義

動作言語の1フレームは、次の形式で表す。

```text
<軸ID量子化値軸ID量子化値...>
```

軸IDの順序はA〜Vで固定する。量子化レベルは全軸10段階で、値は0〜9である。

| ID | joint_idx | axis_idx | 軸 | 最小値 | 最大値 |
|---|---:|---:|---|---:|---:|
| A | 0 | 0 | hips Roll | -50 | 50 |
| B | 0 | 1 | hips Pitch | -30 | 45 |
| C | 0 | 2 | hips Yaw | -40 | 40 |
| D | 1 | 0 | neck Roll | -50 | 50 |
| E | 1 | 1 | neck Pitch | -50 | 60 |
| F | 1 | 2 | neck Yaw | -60 | 60 |
| G | 3 | 0 | L_shoulder Roll | -90 | 90 |
| H | 3 | 1 | L_shoulder Pitch | -30 | 135 |
| I | 3 | 2 | L_shoulder Yaw | -70 | 90 |
| J | 4 | 1 | L_elbow Pitch | -5 | 145 |
| K | 6 | 0 | R_shoulder Roll | -90 | 90 |
| L | 6 | 1 | R_shoulder Pitch | -30 | 135 |
| M | 6 | 2 | R_shoulder Yaw | -70 | 90 |
| N | 7 | 1 | R_elbow Pitch | -5 | 145 |
| O | 9 | 0 | L_hip Roll | -20 | 45 |
| P | 9 | 1 | L_hip Pitch | -15 | 125 |
| Q | 9 | 2 | L_hip Yaw | -45 | 45 |
| R | 10 | 1 | L_knee Pitch | 0 | 130 |
| S | 12 | 0 | R_hip Roll | -20 | 45 |
| T | 12 | 1 | R_hip Pitch | -15 | 125 |
| U | 12 | 2 | R_hip Yaw | -45 | 45 |
| V | 13 | 1 | R_knee Pitch | 0 | 130 |

論理上の定義は次の形式で表現する。

```text
"A": (joint_idx, axis_idx, "range", 10, min_deg, max_deg)
```

## 6. 量子化

角度 `v`、可動域 `[min, max]`、レベル数 `L=10` に対して、まず可動域内にクリップする。

```text
v_clip = min(max(v, min), max)
position = (v_clip - min) / (max - min)
q = floor(position * L)
q = min(max(q, 0), L - 1)
```

最初のフレームは全軸を出力する。2フレーム目以降は、量子化値が前フレームから変化した軸だけを出力する。

例:

```text
<A0B4C6D9>
<D7H6>
<>
```

`<>` は、そのフレームで変化した軸がないことを表す。

## 7. デコード

デコーダはフレーム間で軸の状態を保持する。

1. 初期状態を `(15, 3)` のゼロ配列にする。
2. 各フレームのトークンを左から順に読み取る。
3. 量子化値を角度の中心値へ戻す。
4. 指定された関節・軸だけ状態を更新する。
5. 更新後の状態をフレームとして保存する。

逆量子化は次の式で行う。

```text
angle = min + (max - min) * (q + 0.5) / L
```

量子化値が0〜9の範囲外、未知の軸ID、重複した軸ID、形式不正の行はエラーとする。空の `<>` は有効なフレームである。

ログファイルは、1フレームを1行にしたUTF-8テキストとする。

## 8. 角度から座標への再構成

デコーダで得た角度配列 `(frames, 15, 3)` を使用する。

各関節のローカル回転行列は、角度 `[Roll, Pitch, Yaw]` から次で作る。

```text
R_local = Rz(Roll) @ Rx(Pitch) @ Ry(Yaw)
```

hipsの位置を原点 `(0, 0, 0)` とし、hipsのグローバル回転を `R_local(hips)` とする。子関節は親からの固定骨ベクトルを使って次のように求める。

```text
position_child = position_parent + R_global_parent @ bone_parent_child
R_global_child = R_global_parent @ R_local_child
```

現行の可視化用骨ベクトルは `visualize_motion.py` の `BONE_VECTORS` に定義されている。別システムでは同じ骨長・符号・親子関係を使用しない限り、座標結果は一致しない。

表示上はX軸を左右、Y軸を上下、Z軸を奥行きとし、XY平面を正面とする。

## 9. 移植時の互換性注意

角度計算・再構成は15関節配列を使用するが、動作言語化するのは次の10関節である。

```text
hips, neck,
L_shoulder, L_elbow, R_shoulder, R_elbow,
L_hip, L_knee, R_hip, R_knee
```

次の5関節は動作言語の軸定義から除外する。

```text
head, L_wrist, R_wrist, L_ankle, R_ankle
```

したがって、デコーダの出力は互換性のため `(frames, 15, 3)` のままだが、非ゼロの動作言語軸はA〜Vの22軸だけである。除外された5関節の角度は初期状態の0度として扱われる。

## 10. 参照コマンド

ログを読み込み、デコードと座標再構成を確認する。

```bash
PYENV_VERSION=system python3 \
  src/pose_estimation/visualize_motion.py \
  data_logs/motion/motion_log_YYYYMMDD_HHMMSS_ffffff.txt
```

非GUIで形状だけ確認する場合は `--no-show` を付ける。

```bash
PYENV_VERSION=system python3 \
  src/pose_estimation/visualize_motion.py \
  data_logs/motion/motion_log_YYYYMMDD_HHMMSS_ffffff.txt \
  --no-show
```
